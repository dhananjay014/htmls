Industrial generative recommendation · 2025

Generate the whole slate, then align it to preference.

OneRec replaces a retrieve–pre-rank–rank cascade with one encoder-decoder model that emits a short video session. Sparse experts scale capacity; a reward model turns self-generated sessions into DPO preference pairs.

single-stage generationbalanced semantic IDssession-wise objectivetop-2 MoEiterative preference alignment

The complete system

Unify

Remove handoffs whose recall errors permanently cap downstream rankers.

Generate lists

Model dependencies among displayed items instead of predicting each independently.

Scale sparsely

Use many decoder FFN experts while activating only a small top-k per token.

Align iteratively

Mine personalized winner/loser sessions from the model’s own current outputs.

Three levels of optimization

Item level

Balanced residual k-means creates compact, hierarchical video tokens with less code-distribution skew.

Session level

The decoder predicts a coherent set of 5–10 videos, conditioning every later item on earlier generated choices.

Preference level

A personalized reward model scores watch-time and interaction objectives, creating hard preference pairs for DPO.

Memory hook

Balanced codes name videos → one model generates a session → a reward model chooses the better session → DPO teaches the next model snapshot.

Step 1 · Remove the cascade boundary

A ranker cannot recover what retrieval discarded.

Traditional recommenders reduce a vast catalog through several locally trained stages. OneRec treats the final displayed list as the direct output of a single generative policy.

Cascade architecture

~10¹⁰ videosfull corpus
→
~10⁵ candidatesretrieval
→
~10³ candidatescoarse ranking
→
~10² candidatesfine ranking
→
dozensdisplay list
Recall ceiling propagates\[\text{relevant item }i\notin C_{retrieval}\quad\Longrightarrow\quad i\notin C_{prerank}\quad\Longrightarrow\quad i\notin C_{rank}\]

Even a perfect final ranker cannot select an item removed earlier. Each stage is also usually trained with its own surrogate objective, candidate distribution, and features, creating mismatch.

OneRec architecture

What is gained—and what changes

Potential gains

  • End-to-end objective on final session outputs.
  • No stage-wise candidate ceiling.
  • Direct modeling of list context and diversity.
  • Capacity can scale through sparse decoder experts.

New burdens

  • Autoregressive latency and beam search.
  • Harder control over invalid, duplicate, or unsafe outputs.
  • Reward model quality becomes central.
  • Catalog updates require consistent tokenization and serving constraints.
Unified does not mean objective-free.

The model still optimizes next-token likelihood and learned preference rewards. If those targets omit business constraints or user welfare, end-to-end training can optimize the wrong thing more efficiently.

Step 2 · Name ten billion videos compactly

Balanced residual codes prevent an hourglass.

OneRec starts from multimodal video embeddings aligned to behavior data, then applies residual k-means level by level. Unlike ordinary nearest-centroid assignment, each cluster is forced to receive the same number of items.

Residual code recursion

For video embedding \(e_i\in\mathbb{R}^d\)

1
\[r_i^{1}=e_i\]
Start with the full embedding.The embedding is multimodal and behavior-aligned before quantization.
2
\[s_i^{\ell}=\arg\min_k\|r_i^{\ell}-c_k^{\ell}\|_2^2\]
Pick a centroid index.This integer is level \(\ell\)’s semantic token.
3
\[r_i^{\ell+1}=r_i^{\ell}-c_{s_i^{\ell}}^{\ell}\]
Quantize the remaining error.Later levels refine what earlier levels missed.
4
\[\operatorname{SID}(v_i)=(s_i^1,s_i^2,\ldots,s_i^L)\]
Use the tuple as the video address.The paper’s deployment uses \(L=3\) codebook levels.

What “balanced k-means” adds

Equal-capacity assignment\[w=\frac{|V|}{K},\qquad |V_k|=w\ \text{ for every cluster }k\]

At each iteration, each centroid takes its \(w\) nearest currently unassigned items, then updates to their mean. This prevents a few popular centroids from absorbing most videos while other codes remain almost unused.

Production configuration in the paper

8192clusters per codebook

Each token position chooses among a large but manageable vocabulary.

3codebook levels

One video is represented by three hierarchical tokens.

8192³raw tuple capacity

Theoretical address space is far larger than the actual catalog; valid decoding must stay on used tuples.

Relationship to RQ-VAE

Both methods subtract selected code vectors level by level. OneRec replaces the learned RQ-VAE tokenizer used by TIGER with balanced residual k-means over its behavior-aligned multimodal embeddings.

Step 3 · Predict a list, not isolated points

Later recommendations see earlier choices.

A session is the batch of videos returned for one request—typically 5 to 10. OneRec autoregressively generates that entire list, so coherence and diversity become modelable dependencies.

Point-wise vs session-wise

Independent next-item scoring\[p(v_j\mid H_u)\quad\text{for each }j\]

A hand-built policy must combine individually good items into one slate.

Session-wise generation\[p(S\mid H_u)=\prod_{j=1}^{m}p(v_j\mid H_u,v_{\lt j})\]

Each choice conditions on what is already in the session.

Training data: what counts as a good session?

The paper extracts sessions from logged requests and keeps high-quality ones using engagement conditions. Examples include at least five actually watched videos, sufficient cumulative watch duration, or interactions such as likes, collections, or shares.

This is selective imitation.

Next-token training learns from sessions already filtered as high value. It does not directly discover a globally optimal slate; it imitates the distribution created by the existing system and the filtering policy.

Next-token objective

Flattened session tokens\[\bar S=[BOS,s_1^1,\ldots,s_1^L,BOS,s_2^1,\ldots,s_2^L,\ldots,BOS,s_m^1,\ldots,s_m^L]\]
Teacher-forced likelihood\[\mathcal L_{NTP}=-\sum_{t=1}^{m(L+1)}\log p_\theta(\bar S_{t+1}\mid H_u,\bar S_{\le t})\]

What list context can learn

Coherence

After a cooking clip, another related clip may fit a session better than an unrelated high-score item.

Diversity

After two near-duplicate sports clips, probability can shift toward a complementary topic.

Ordering

A broad-interest item can precede a niche follow-up; order can affect whether the user reaches later videos.

Exposure confoundingLogged “good sessions” reflect what the old recommender chose to show.
Error propagationAn early decoding mistake becomes context for every later session item.
Duplicate controlAutoregressive likelihood alone does not guarantee unique items; decoding constraints may be needed.
LatencyGenerating (mL) tokens with beam search is more sequential than scoring a fixed candidate matrix.
Step 4 · Add capacity without dense FLOPs

Every token chooses two of twenty-four experts.

OneRec replaces decoder feed-forward sublayers with sparse Mixture-of-Experts layers. All experts are parameters; only the top-(K) gate choices execute for a token.

Routing and layer equations

For \(N_E\) experts and top-\(K_E\) routing

1
\[s_{i,t}=\operatorname{softmax}_i\!\left((h_t^\ell)^\top e_i^\ell\right)\]
Score expert affinity.Each expert has a learned router vector \(e_i^\ell\).
2
\[g_{i,t}=\begin{cases}s_{i,t},&i\in\operatorname{TopK}(s_{\cdot,t},K_E)\\0,&\text{otherwise}\end{cases}\]
Sparsify the gate.Only selected experts receive this token and consume FFN compute.
3
\[h_t^{\ell+1}=h_t^\ell+\sum_{i=1}^{N_E}g_{i,t}\operatorname{FFN}_i(h_t^\ell)\]
Combine active experts.Inactive experts add parameters but no token-level FFN FLOPs for this pass.

Paper configuration

24total experts per MoE layer

Capacity lives across many specialist FFNs.

2active experts per token

Top-2 routing bounds the dominant FFN computation.

13%parameters active at inference

Reported for the deployed model; attention and shared components remain dense.

Why more parameters can help

Conditional specialization

Tokens for different content clusters, users, or semantic-code levels can learn to route to different FFN subspaces.

Capacity/FLOP decoupling

Total parameters grow with \(N_E\), while per-token expert FLOPs grow mainly with \(K_E\), assuming balanced routing and efficient dispatch.

Load imbalancePopular experts can overflow capacity while others remain undertrained.
CommunicationDispatching tokens across devices can dominate nominal FFN arithmetic.
Router collapseWithout balancing losses or capacity controls, many tokens may select the same experts.
Memory remainsInactive experts still occupy parameter storage and must be sharded or loaded.
Step 5 · Align generated sessions

The model creates its own hard negatives.

Recommendation logs rarely contain two sessions shown to the same user at the same moment. OneRec trains a reward model, samples many current-model sessions, and uses the highest- and lowest-scoring outputs as a personalized preference pair.

Personalized session reward model

Iterative Preference Alignment loop

Build the next model \(M_{t+1}\) from current model \(M_t\)

1
\[S_u^n\sim M_t(H_u),\qquad n=1,\ldots,N\]
Explore current behavior.The paper uses beam search to generate \(N=128\) candidate sessions for sampled users.
2
\[r_u^n=R(u,S_u^n),\quad S_u^w=\arg\max_n r_u^n,\quad S_u^l=\arg\min_n r_u^n\]
Mine self-hard preferences.The winner and loser are personalized and lie on the current model’s output distribution.
3
\[\mathcal L_{DPO}=-\log\sigma\!\left(\beta\log\frac{M_{t+1}(S^w\mid H)}{M_t(S^w\mid H)}-\beta\log\frac{M_{t+1}(S^l\mid H)}{M_t(S^l\mid H)}\right)\]
Increase winner-relative likelihood.The previous snapshot \(M_t\) serves as the DPO reference policy.
4
\[\mathcal L=\mathcal L_{NTP}+\lambda\mathcal L_{DPO}\]
Keep language-model grounding.NTP anchors the generator to high-quality sessions while DPO shifts preference between sampled alternatives.

Why only 1% DPO sampling?

Beam-generating 128 sessions and scoring each is expensive. The paper applies DPO sampling to only \(r_{DPO}=1\%\) of examples; its ablation reports marginal gains from increasing to 5% despite roughly linear sampling-resource growth.

The reward model becomes the optimization target.

If it misranks sessions, IPA confidently amplifies those errors. Self-generated pairs reduce off-policy mismatch but do not make the reward unbiased or immune to reward hacking.

2 · Route a decoder token

At one decoding position, suppose the router’s largest expert probabilities are expert 4 at 0.52 and expert 17 at 0.31. Top-2 routing zeros the rest:

Sparse FFN update\[h'=h+0.52\operatorname{FFN}_4(h)+0.31\operatorname{FFN}_{17}(h)\]

The gate is sparse but not necessarily renormalized after top-k in the paper’s displayed equation; implementation details can choose normalization and load-balancing behavior.

4 · See the DPO margin move

Let the new model improve the winner log-probability relative to the old snapshot by \(+1.2\), while its loser relative log-probability changes by \(-0.4\). With \(\beta=0.1\):

Pairwise preference loss

1
\[m=(+1.2)-(-0.4)=1.6\]
Compute relative preference margin.Winner change minus loser change.
2
\[\beta m=0.16,\qquad \sigma(0.16)\approx0.540\]
Convert to pair probability.The model has moved modestly toward the desired ordering.
3
\[\mathcal L_{DPO}=-\log 0.540\approx0.616<0.693\]
Loss falls from the zero-margin baseline.Gradient keeps rewarding a larger winner-over-loser relative margin.

Reasoning check

Why not train only on the reward model’s top session and discard NTP?

That would aggressively optimize a learned proxy on a tiny self-selected subset and can drift away from valid, diverse, high-quality session generation. NTP anchors the model to logged good sessions; DPO supplies a relative correction between current-model alternatives.
Production system · Claims in context

Offline gains became an online watch-time lift.

The paper reports a deployed 1B-parameter model on Kuaishou, with a separate DPO sampling service, reward model, training stack, and online inference model.

Offline ablation takeaways

Session-wise beats point-wise.

OneRec-1B exceeds TIGER-1B on reported maximum session watch time and like-rate metrics, supporting list-context modeling in this setup.

IPA beats listed preference baselines.

The iterative self-hard sampling strategy reports stronger metrics than DPO, IPO, cDPO, rDPO, CPO, SimPO, and S-DPO variants.

Model scale helps through 1B.

The paper reports consistent offline gains from 0.05B to 1B, with sparse experts decoupling total capacity from active compute.

More DPO data has diminishing returns.

Increasing sampling from 1% to 5% raises GPU demand roughly fivefold while adding little average quality.

Limitations and audit notes

Private evaluationData, production baseline, reward labels, and serving stack are not independently reproducible from the paper.
Reward-model dependenceOffline metrics are themselves reward-model predictions; online A/B evidence is therefore especially important.
Multi-objective gapThe authors report limitations on interaction indicators such as likes despite watch-time gains.
Preprint metadataThe PDF still contains placeholder conference/copyright metadata; treat it as arXiv v1 rather than a finalized venue paper.
Feedback loopsTraining on logged exposure and then self-generated reward pairs can amplify existing preferences and blind spots.
Operational complexity“One model” still requires tokenization, distributed MoE, beam serving, reward inference, sampling, and continuous synchronization.

Interview drill

Why session-wise?

It conditions each recommendation on prior slate choices, allowing learned coherence, diversity, and ordering instead of post-hoc rules.

Why balanced codes?

To prevent upper-level code skew from forming an hourglass that wastes token capacity and burdens the generator.

Why MoE only in decoder FFNs?

It expands conditional generation capacity while keeping per-token active FFN compute near top-\(K\), though attention remains dense.

Why a reward model?

Online recommendation usually exposes one session, so simultaneous human winner/loser labels are unavailable; the model scores counterfactual generated sessions.

Why iterative DPO?

Current-model samples are hard, on-distribution alternatives. Updating pairs after the policy changes avoids training forever on stale negatives.

Main risk?

Reward-model and exposure bias can be amplified by self-training; online multi-objective evaluation is essential.
