Transformer foundations · fully numerical

Attention is a learned weighted lookup.

For every token, self-attention asks: “Which tokens matter to me right now, and what information should I collect from them?” The answer is built from matrix multiplication, scaling, masking, row-wise softmax, and a weighted sum—nothing is skipped in this guide.

The whole operation in one picture

Scaled dot-product attention \[\operatorname{Attention}(Q,K,V) =\operatorname{softmax}_{\text{keys}}\!\left(\frac{QK^\top}{\sqrt{d_k}}+M\right)V\]

Equivalent mask conventions are common. This guide uses \(QK^\top/\sqrt{d_k}+M\), where allowed entries of \(M\) are \(0\) and forbidden entries are \(-\infty\). Putting \(M\) inside the numerator is fine only if it has been scaled consistently.

Query · what I seek

Token \(i\) projects to \(q_i\). That vector determines what kinds of keys token \(i\) will score highly.

Key · what I match on

Token \(j\) projects to \(k_j\). The dot product \(q_i\cdot k_j\) is their learned compatibility score.

Value · what I send

Token \(j\) also projects to \(v_j\). Once weights are known, values—not keys—are averaged into the output.

Self-attention versus ordinary lookup

A database lookup uses a fixed key.

You supply one query, retrieve matching records, and return their stored values.

Self-attention learns all three roles.

Every input row creates its own query, key, and value. Every query compares with every key in one batched matrix product.

“Self” describes the source.

Queries, keys, and values all come from the same sequence \(X\). Cross-attention instead takes queries from one sequence and keys/values from another.

The output is contextual.

The embedding for “bank” can become river-like or finance-like because its output mixes different neighbors in different contexts.

Memory hook

Queries choose. Keys compete. Values contribute. Softmax makes each query’s choices sum to one.

Step 1 · Construct the input matrix

Three tokens, four numbers per token.

Our running example uses the sequence “I love ML,” one batch item, and deliberately small vectors. Real models use the same operations with hundreds or thousands of dimensions.

\(B=1\)batch size
\(n=3\)sequence length
\(d_{\text{model}}=4\)embedding / residual width
\(h=2\)attention heads later
\(d_k=2\)query/key width per head
\(d_v=2\)value width per head

Token embedding plus position

The embedding table itself has shape \([|\mathcal V|,d_{\text{model}}]\), where \(|\mathcal V|\) is vocabulary size. Looking up three tokens selects three rows, producing \(E\in\mathbb R^{3\times4}\). Positional vectors \(P\) have the same width so they can be added elementwise.

Position is not optional

Without any position signal, self-attention is permutation-equivariant: reordering input rows simply reorders output rows. The original Transformer adds sinusoidal positional encodings; many later models use learned absolute positions or relative/rotary schemes. All provide order information that the content embeddings alone do not contain.

Do not confuse width with length.

\(n=3\) counts tokens. \(d_{\text{model}}=4\) counts features per token. Attention scores form an \(n\times n\) matrix, not a \(d_{\text{model}}\times d_{\text{model}}\) matrix.

Step 2 · Follow the five operations

Shapes tell you whether the math is possible.

Keep the token axis on the left and the feature axis on the right. Every equation becomes easier once you can say what each row and column means.

Input\(X:[n,d_{\text{model}}]\)one state per token
Project\(Q,K:[n,d_k]\)\(V:[n,d_v]\)
Compare\(QK^\top:[n,n]\)query rows × key columns
Normalize\(A:[n,n]\)each row sums to 1
Collect\(AV:[n,d_v]\)one context per query

Scaled dot-product attention, dimension by dimension

1
\[Q=XW^Q,\quad K=XW^K,\quad V=XW^V\]
Learn three views of every token.\([n,d_{\text{model}}][d_{\text{model}},d_k]\to[n,d_k]\) for queries and keys; values may use width \(d_v\).
2
\[R=QK^\top,\qquad R_{ij}=q_i\cdot k_j\]
Compare every query with every key.\([n,d_k][d_k,n]\to[n,n]\). Row \(i\) belongs to query \(i\); column \(j\) belongs to key \(j\).
3
\[S=\frac{R}{\sqrt{d_k}}+M\]
Control magnitude and legality.Scaling stabilizes softmax; \(M\) sets forbidden key positions to \(-\infty\).
4
\[A_{ij}=\frac{\exp(S_{ij})}{\sum_{\ell=1}^{n}\exp(S_{i\ell})}\]
Normalize across keys.Softmax runs along the last axis. Every query row becomes a distribution over source positions.
5
\[H=AV,\qquad h_i=\sum_{j=1}^{n}A_{ij}v_j\]
Mix value content.\([n,n][n,d_v]\to[n,d_v]\). Each query keeps its row position but receives a contextual value mixture.

Why divide by \(\sqrt{d_k}\)?

If components of \(q\) and \(k\) are independent with mean \(0\) and variance \(1\), then \(q\cdot k=\sum_{\ell=1}^{d_k}q_\ell k_\ell\) has variance \(d_k\). Its typical magnitude therefore grows like \(\sqrt{d_k}\). Large logits make softmax nearly one-hot and its gradients tiny; dividing by \(\sqrt{d_k}\) keeps the scale more stable.

Same raw score row: \([5,2,3]\)Compare softmax before and after scaling by \(\sqrt{2}\)
Sharper than necessary \[\operatorname{softmax}([5,2,3]) =\frac{[1,e^{-3},e^{-2}]}{1+e^{-3}+e^{-2}} =[0.8438,0.0420,0.1142]\]
The calculation used in our example \[\operatorname{softmax}\!\left(\frac{[5,2,3]}{\sqrt2}\right) =\frac{[1,e^{-2.1213},e^{-1.4142}]}{1+e^{-2.1213}+e^{-1.4142}} =[0.7337,0.0879,0.1784]\]

What softmax is—and is not—doing

It is row-local.

Changing query \(i\) changes row \(i\). Other rows have their own denominators.

It creates competition.

Increasing one key’s weight lowers the remaining weights because a row must sum to one.

It does not mix values yet.

The matrix \(A\) contains routing weights. Content moves only when \(A\) multiplies \(V\).

Step 3 · Control who may look where

A mask changes the softmax support.

A causal decoder must not use future tokens. Add \(-\infty\) to forbidden logits before softmax; their exponentials become zero, so they receive exactly zero probability.

Causal mask for three positions

Mask \[ M_{\text{causal}}= \begin{bmatrix} 0&-\infty&-\infty\\ 0&0&-\infty\\ 0&0&0 \end{bmatrix} \]

Row 1 sees only position 1; row 2 sees positions 1–2; row 3 sees all three.

Allowed region \[ j\le i\Rightarrow M_{ij}=0,\qquad j>i\Rightarrow M_{ij}=-\infty \]

The diagonal remains visible, so a token may attend to itself.

Using the first head from our worked example, the unmasked scaled logits are:

Before and after causal masking \[ S= \begin{bmatrix} 3.5355&1.4142&2.1213\\ 1.4142&0.7071&0.7071\\ 2.1213&0.7071&1.4142 \end{bmatrix} \] \[ S+M_{\text{causal}}= \begin{bmatrix} 3.5355&-\infty&-\infty\\ 1.4142&0.7071&-\infty\\ 2.1213&0.7071&1.4142 \end{bmatrix} \]
Row 1\(\operatorname{softmax}([3.5355,-\infty,-\infty])=[1,0,0]\)
Row 2\(\frac{[1,e^{-0.7071},0]}{1+e^{-0.7071}}=[0.6698,0.3302,0]\)
Row 3No future key exists, so it stays \([0.5760,0.1400,0.2840]\).
Causal attention weights and outputs \[ A_{\text{causal}}= \begin{bmatrix} 1&0&0\\ 0.6698&0.3302&0\\ 0.5760&0.1400&0.2840 \end{bmatrix} \] \[ A_{\text{causal}}V= \begin{bmatrix} 2.0000&-1.0000\\ 1.5046&-0.1744\\ 1.5060&-0.0819 \end{bmatrix} \]
Row 2 check: \(0.6698[2,-1]+0.3302[0.5,1.5]=[1.5046,-0.1744]\).

Padding masks solve a different problem

Causal mask

Blocks information from future key positions. It depends on relative query/key position.

Padding mask

Blocks artificial pad tokens in the key columns. It depends on which sequence positions are real.

If token 3 were padding, its key column would receive \(-\infty\) in every row. Implementations commonly combine padding and causal masks by addition or a boolean OR before softmax.

Mask before softmax.

Zeroing attention weights after softmax breaks normalization unless you renormalize. Adding a large negative number or \(-\infty\) to logits is the standard operation.

Step 4 · Run several attention spaces

Each head gets its own way to compare tokens.

Multi-head attention does not copy one attention map. It learns separate query, key, and value projections, performs a separate softmax in every head, concatenates the head outputs, and mixes them with one output projection.

Multi-head attention \[ \operatorname{head}_r= \operatorname{Attention}(XW_r^Q,XW_r^K,XW_r^V) \] \[ \operatorname{MHA}(X)= \operatorname{Concat}(\operatorname{head}_1,\ldots,\operatorname{head}_h)W^O \]
ParameterGeneral shapeOur two-head exampleOriginal Transformer base
\(W_r^Q,W_r^K\)\([d_{\text{model}},d_k]\) per head\([4,2]\)\([512,64]\), \(h=8\)
\(W_r^V\)\([d_{\text{model}},d_v]\) per head\([4,2]\)\([512,64]\)
Concatenated heads\([n,h\,d_v]\)\([3,4]\)\([n,512]\)
\(W^O\)\([h\,d_v,d_{\text{model}}]\)\([4,4]\)\([512,512]\)

Why not use one wide head?

Separate routing patterns

One head may emphasize nearby syntax while another emphasizes a distant entity or delimiter.

Separate representation subspaces

Each head learns different \(W^Q,W^K,W^V\), so “match” and “content” mean different things per head.

Similar total width

When \(d_k=d_v=d_{\text{model}}/h\), splitting into heads keeps concatenated width at \(d_{\text{model}}\).

Parameter count in our tiny layer

Per head\[3(4\times2)=24\ \text{weights}\]

Eight each for query, key, and value projections.

Two heads + output\[2(24)+(4\times4)=64\ \text{weights}\]

Biases omitted. This equals four dense \(4\times4\) maps when Q/K/V are packed.

Worked example A · one complete head

Calculate self-attention without hiding a step.

We now carry the \(3\times4\) input matrix through projections, nine dot products, scaling, three separate softmax calculations, and three weighted value sums.

Rounding policy

Projection and dot-product values are exact. Exponentials, attention weights, and outputs are shown to four decimals. The calculations use unrounded values internally, so a last decimal may differ from hand arithmetic on displayed numbers.

Dimension check

Why does \(A_1:[3,3]\) times \(V_1:[3,2]\) produce three rows rather than two?

Matrix multiplication contracts the shared inner token axis \(3\): \([3,3][3,2]\to[3,2]\). The first 3 is the number of queries, so one output row remains for each query token. The final 2 is the value width.

Engineering view · batch and head axes

Production tensors add two axes, not new math.

Libraries keep batch and head axes explicit for the attention matmuls. A common implementation packs all projection weights into one QKV linear layer, then reshapes rather than looping over heads.

What reshape and transpose actually do

Reference pseudocode with every shape

PyTorch-like pseudocode; \(d_h=d_{\text{model}}/h\) 
x                 # [B, n, d_model]
qkv = qkv_linear(x)                     # [B, n, 3*d_model]
qkv = qkv.reshape(B, n, 3, h, d_h)      # [B, n, 3, h, d_h]
qkv = qkv.permute(2, 0, 3, 1, 4)        # [3, B, h, n, d_h]
q, k, v = qkv[0], qkv[1], qkv[2]        # each [B, h, n, d_h]

scores = q @ k.transpose(-2, -1)         # [B, h, n, n]
scores = scores / sqrt(d_h)
scores = scores + mask                   # broadcastable to [B, h, n, n]
weights = softmax(scores, dim=-1)        # normalize over key positions
heads = weights @ v                      # [B, h, n, d_h]

concat = heads.transpose(1, 2)           # [B, n, h, d_h]
concat = concat.reshape(B, n, d_model)   # [B, n, d_model]
out = output_linear(concat)              # [B, n, d_model]

A full dense MHA implementation is therefore \(O(nd_{\text{model}}^2+n^2d_{\text{model}})\) per sequence, with an explicit score/weight memory term \(O(hn^2)\). At modest lengths, projections may dominate compute; at long lengths, the quadratic attention terms dominate.

Cross-attention changes the two length axes

Queries and memory can have different lengths \[ Q:[B,h,n_q,d_k],\qquad K,V:[B,h,n_{kv},d_k\text{ or }d_v] \] \[ QK^\top:[B,h,n_q,n_{kv}],\qquad AV:[B,h,n_q,d_v] \]

Self-attention is the special case \(n_q=n_{kv}=n\) with all three projections sourced from the same sequence.

Reasoning and debugging

Most attention bugs are axis bugs.

The formulas are short; implementations fail when token, head, batch, and feature axes are confused—or when a mathematically valid operation means something different from the intended one.

Common mistakes

Softmax over queriesUsing the wrong axis makes columns sum to one. Normalize over keys: typically dim=-1.
Scaling by \(\sqrt{d_{\text{model}}}\)The dot product has \(d_k\) terms, so the denominator is \(\sqrt{d_k}\), the per-head key width.
Masking after softmaxForbidden positions may retain mass or rows stop summing to one. Mask logits first.
Multiplying weights by \(K\)Keys determine routing; values carry content. The output is \(AV\), not \(AK\), unless a model deliberately ties them.
Dropping the output projectionConcatenation alone leaves heads isolated. \(W^O\) mixes their feature subspaces and restores residual width.
Forgetting positionsContent-only self-attention cannot distinguish permutations except through other order signals.
Assuming \(d_k=d_v\) is requiredIt is common, not mandatory. Query and key widths must match each other; value width may differ.
All-masked rowsSoftmax of all \(-\infty\) is undefined. Avoid such rows or handle padded query outputs explicitly.

Invariants that catch bugs quickly

Rows sum to one.

For every valid batch/head/query row, \(\sum_jA_{ij}\approx1\).

Masked weights are zero.

Inspect probabilities, not merely masked logits.

Shapes survive round trips.

Splitting and recombining heads must return \([B,n,d_{\text{model}}]\).

Weights are nonnegative.

Softmax produces \(A_{ij}\ge0\); negative values can still make outputs negative.

Identical values stay identical.

If all \(v_j=c\), then every valid \(h_i=c\), regardless of attention weights.

Causal prefixes are stable.

Changing a future token must not change earlier causal outputs.

What attention weights do not prove

Not automatically an explanation

A high weight says a value contributed strongly in that head at that layer. Residual paths, value projections, later layers, and nonlinearities still shape the prediction.

Not guaranteed head specialization

Heads can become redundant, diffuse, or difficult to label. “One syntax head, one entity head” is an intuition, not a training constraint.

Not the entire Transformer block

Attention moves information across positions. Position-wise feed-forward networks transform features within each position.

Not cheap at every sequence length

Dense score and weight matrices grow quadratically with \(n\), motivating local, sparse, linear, and fused attention methods.

Subtleties in real implementations

Numerical stabilitySubtract maxima inside softmax.

Framework softmax kernels do this; mixed-precision implementations may accumulate or upcast selected operations.

DropoutTraining may drop attention probabilities.

Dropout is often applied to \(A\) after softmax. Surviving probabilities are rescaled during training, so a sampled row need not visually sum to one.

Fused kernelsThe full \(n\times n\) matrix need not be materialized.

Exact fused algorithms can tile Q/K/V and compute softmax online, reducing memory traffic while preserving the mathematical result.

Grouped-query variantsQuery heads may outnumber key/value heads.

Multi-query and grouped-query attention share K/V projections across groups to reduce cache size. Standard MHA uses equal Q, K, and V head counts.

Debugging question

Your attention tensor has shape \([B,h,n,n]\), but each column sums to one and each row does not. What is the most likely mistake?

Softmax was applied over the query axis (the second-to-last axis) instead of the key axis (the last axis). Use row-wise softmax over key positions.

Interview drill

Why scale by \(\sqrt{d_k}\)?

A dot product of \(d_k\) unit-variance terms has variance \(d_k\). Scaling prevents increasingly saturated softmax logits.

Why separate K and V?

The representation useful for deciding relevance need not be the representation useful to transfer after relevance is decided.

Which axis gets softmax?

The key/source axis. Each query row chooses a distribution over keys.

Why use multiple heads?

Different projections and softmaxes let the layer route through multiple representation subspaces simultaneously.

Why is \(W^O\) needed?

It mixes concatenated head features and returns the result to \(d_{\text{model}}\) for the residual stream.

Where does quadratic cost arise?

Every query-key pair creates a score, producing \(n^2\) entries per head.
