Attention systems · exact math, different execution

FlashAttention computes exact attention without materializing the full matrix.

Standard attention often writes an \(N\times N\) score matrix to slow high-bandwidth memory, reads it back for softmax, writes probabilities, and reads them again to mix values. FlashAttention tiles the same calculation into fast on-chip memory and carries only compact running softmax statistics between tiles.

exact attentionHBM vs SRAMonline softmaxtilingbackward recomputation

The central distinction

Mathematical operator\[O=\operatorname{softmax}\!\left(\frac{QK^\top}{\sqrt d}+M\right)V\]

FlashAttention computes this same dense operator, up to ordinary floating-point reordering.

Execution schedule\[\text{load tiles}\rightarrow\text{score}\rightarrow\text{online softmax}\rightarrow\text{accumulate }O\]

The full score and probability matrices do not have to be materialized in HBM.

Memory hook

Do not ask “Which attention approximation does FlashAttention use?” Ask “How can exact softmax attention be evaluated without repeatedly moving its quadratic intermediates through slow memory?”

Step 1 · Find the real bottleneck

Attention can be limited by data movement before arithmetic.

GPU tensor cores can multiply matrices extremely quickly. If every sub-operation spills a large intermediate to HBM, the arithmetic units wait for bytes. FlashAttention is “IO-aware” because its schedule is derived from this asymmetric memory hierarchy.

The standard three-stage implementation

1 · Scoresread Q,K; write \(S=QK^\top/\sqrt d\)
→
2 · Softmaxread S; write \(P=\operatorname{softmax}(S)\)
→
3 · Valuesread P,V; write \(O=PV\)

The exact number of writes depends on the framework and fusion level, but the dangerous objects are always \(S,P\in\mathbb{R}^{N\times N}\) per head. Their size grows with \(N^2\), while \(Q,K,V,O\) grow with \(Nd\).

What FlashAttention does not claim

It is not sparse attention.

Every allowed query–key pair is still evaluated. Causal masking can skip the forbidden upper triangle, but the allowed dense graph remains.

It does not alter model parameters.

Q/K/V/output projections are unchanged. You can replace a compatible attention kernel without retraining the mathematical architecture.

It is not “free \(O(N)\) attention.”

Auxiliary memory can become linear in \(N\), but dense forward arithmetic remains \(O(N^2d)\).

Exact is mathematical, not bitwise.

Changing reduction order can change the last floating-point bits. “Exact” means no low-rank, sparse, or kernel approximation to softmax attention.

Step 2 · Make softmax streamable

Online softmax merges blocks without losing the global denominator.

The obstacle is not the weighted sum—it is softmax’s row-wide maximum and denominator. Running statistics let a new score block revise both safely.

Start with safe softmax

One score row \(s\) \[ m=\max_j s_j,\qquad \ell=\sum_j e^{s_j-m},\qquad p_j=\frac{e^{s_j-m}}{\ell} \]

Subtracting \(m\) prevents overflow without changing probabilities. Online softmax stores the current maximum \(m\), shifted exponential sum \(\ell\), and unnormalized value accumulator \(\widetilde o\).

Merge one new block

Old state \((m,\ell,\widetilde o)\) + a block \((s_B,V_B)\)

1
\[\widetilde m=\max(s_B),\qquad m'=\max(m,\widetilde m)\]
Choose one shared reference maximum.If the new block has a larger logit, old exponentials must be rescaled.
2
\[\ell'=e^{m-m'}\ell+\sum_{j\in B}e^{s_j-m'}\]
Merge denominators.The first factor converts the old shifted sum to the new maximum’s coordinate system.
3
\[\widetilde o'=e^{m-m'}\widetilde o+\sum_{j\in B}e^{s_j-m'}v_j,\qquad o=\widetilde o'/\ell'\]
Merge value numerators the same way.After the final block, divide once to obtain exactly the full softmax-weighted value.
The invariant

After any number of blocks, \(\ell=\sum e^{s_j-m}\) and \(\widetilde o=\sum e^{s_j-m}v_j\) over every score seen so far. The physical block boundary disappears from the final ratio.

Initialization

\[m_0=-\infty,\qquad \ell_0=0,\qquad \widetilde o_0=\mathbf 0\]

The first real block automatically replaces the maximum and contributes all mass. Masked values behave like logits of \(-\infty\): their exponential contribution is zero.

FA1 versus this pseudocode. The original paper’s loop organization loads a K/V tile and visits query tiles, periodically reading/writing output statistics. FlashAttention-2 changes loop order and work partitioning to reduce non-matmul work and communication. The invariant above is shared.

Fusion is as important as tiling

Score fragment

Compute \(Q_iK_j^\top\) with tensor-core-friendly matrix multiplication.

Mask + softmax

Apply scale, bias/mask, maximum, exponentials, and denominator updates before the fragment leaves the chip.

Value accumulation

Immediately multiply local probabilities by \(V_j\) and add them to the rescaled output numerator.

Tile A uses local maximum 2. Its shifted weights are \([e^{-1},1]\), so \(\ell=e^{-1}+1\) and \(\widetilde o=e^{-1}[1,0]+[0,2]\).

1 · Process tile A

\[ m_A=2,\qquad \ell_A=e^{1-2}+e^{2-2}=e^{-1}+1=1.367879 \] \[ \widetilde o_A=e^{-1}[1,0]+1[0,2]=[0.367879,2] \]

2 · Merge tile B

The new block maximum is 3, so every old contribution must be multiplied by \(e^{2-3}=e^{-1}\).

\[ m_B=\max(2,3)=3 \] \[ \ell_B=e^{-1}(1.367879)+e^{3-3}+e^{0-3} =0.503215+1+0.049787=1.553002 \] \[ \begin{aligned} \widetilde o_B &=e^{-1}[0.367879,2]+1[3,1]+e^{-3}[-1,2]\\ &=[0.135335,0.735759]+[3,1]+[-0.049787,0.099574]\\ &=[3.085548,1.835333]. \end{aligned} \]

3 · Normalize once

\[ o=\frac{\widetilde o_B}{\ell_B} =\frac{[3.085548,1.835333]}{1.553002} =[1.986827,1.181798]. \]

Check against full softmax

\[ \operatorname{softmax}([1,2,3,0]) =\frac{[e^{-2},e^{-1},1,e^{-3}]}{1.553002} =[0.087144,0.236883,0.643914,0.032059] \] \[ \sum_j p_jv_j=[1.986827,1.181798]. \]
Why the rescaling is non-negotiable

If tile B changed the running maximum from 2 to 3 but tile A’s accumulator were left untouched, old and new exponentials would use different reference points. The final ratio would be wrong.

Training · spend arithmetic to save memory traffic

Backward recomputes score tiles instead of saving the attention matrix.

Autograd usually wants softmax probabilities to form gradients. Saving all \(P\) rows recreates the quadratic-memory problem, so FlashAttention stores compact per-row normalization information and regenerates local \(S\) and \(P\) tiles from Q and K during backward.

The checkpointing analogy

Activation checkpointing

Discard selected intermediate activations and rerun a larger network segment during backward.

FlashAttention backward

Discard quadratic attention intermediates and reconstruct only the tile currently needed for gradient calculations.

Dropout detail. A fused training kernel must reproduce the same dropout mask during backward, usually through deterministic counter-based random state rather than storing an \(N\times N\) mask.

Evolution · same operator, newer schedules

Later versions improve utilization and exploit newer GPU instructions.

The online-softmax foundation persists. The version number mostly tells you which hardware and work-partitioning strategy the kernel targets—not a new attention equation.

FA1 · 2022

Introduced IO-aware exact attention with SRAM tiling and backward recomputation. The paper proves an HBM-access advantage under its memory model and demonstrates linear auxiliary memory.

FA2 · 2023

Reduces non-matmul FLOPs, parallelizes a single head across thread blocks when helpful, and repartitions work among warps to reduce shared-memory communication. The paper reports roughly 2× kernel speed over FA1 in tested settings.

FA3 · 2024

Targets Hopper with asynchronous TMA loads, warp specialization, overlapping GEMM and softmax, and an FP8 path with accuracy-aware techniques. It is a hardware-specific evolution, not a universal replacement on older GPUs.

FA4 · 2026

The official repository currently exposes a CuTeDSL implementation optimized for Hopper and Blackwell. Treat installation, supported features, and performance as release-specific facts and check the repository at deployment time.

What did not change

Semantics\[O=\operatorname{softmax}(S)V\]

Dense attention output remains the target.

Core challenge\[\text{maximize useful tensor-core work per HBM byte}\]

Every generation adapts the schedule to the memory hierarchy and execution model.

Do not benchmark version names in the abstract.

Sequence lengths, head dimensions, causal mode, precision, dropout, GPU generation, framework integration, compilation flags, and end-to-end model composition determine the realized speedup.

Implementation lens · shapes and dispatch

Using FlashAttention is a kernel-selection problem with shape constraints.

Model code still supplies Q, K, V, masking mode, scale, and dropout. A framework chooses a compatible fused backend or falls back to another scaled-dot-product-attention implementation.

Typical packed shape

One common API convention \[ Q:[B,N_q,H_q,D],\qquad K,V:[B,N_k,H_{kv},D],\qquad O:[B,N_q,H_q,D]. \]

Self-attention

Usually \(N_q=N_k\). Causal mode forbids query position \(i\) from seeing later key positions.

Cross-attention

\(N_q\) and \(N_k\) may differ. The kernel tiles a rectangular score matrix.

MQA/GQA

\(H_{kv}\lt H_q\). Key/value heads are shared by groups of query heads when the implementation supports it.

Ragged batches

Padding every sequence to the batch maximum wastes pairwise work. Variable-length interfaces concatenate real tokens and pass cumulative sequence offsets so kernels can operate on each sequence’s true boundaries.

\[ \text{padded pairs}=B\,N_{\max}^2,\qquad \text{ragged pairs}\approx\sum_{b=1}^{B}N_b^2. \]

A responsible integration checklist

Confirm dispatch.

Profiler traces should show the intended fused kernel. Merely importing a package does not guarantee every call uses it.

Test numerical tolerances.

Compare outputs and gradients against a trusted reference across causal/non-causal, lengths, precisions, and head dimensions.

Benchmark end to end.

A faster attention kernel may be hidden by projections, MLPs, communication, data loading, or short-sequence overhead.

Keep a fallback.

Unsupported devices, compilation environments, or feature combinations should degrade to a correct alternative.

Boundary conditions · where intuition breaks

FlashAttention removes one bottleneck; it does not remove every attention bottleneck.

Quadratic FLOPs remainAt very long dense contexts, arithmetic itself eventually dominates even if intermediate storage is controlled.
Decoding is differentWith one new query and a large KV cache, the operation is often bandwidth-bound on reading K/V; split-KV or paged-decoding kernels matter.
Hardware specificityTile sizes, warp schedules, precision paths, and supported head dimensions vary across NVIDIA and AMD generations.
Feature matrix variesBiases, arbitrary masks, attention-score outputs, dropout, deterministic backward, and sliding windows may restrict backend choice.
“Memory efficient” is scopedParameters, QKV activations, residual streams, MLP activations, optimizer states, and the KV cache still consume memory.
Speedups are workload claimsPaper results are tied to specific GPUs, shapes, baselines, and software; do not transplant a headline multiplier.

Three common misconceptions

ClaimCorrection
“FlashAttention approximates softmax.”No. It evaluates dense softmax attention with a tiled online reduction.
“It makes attention linear time.”No. It can make auxiliary storage linear; dense score/value arithmetic remains quadratic.
“It stores no attention information.”It avoids the full matrix but retains outputs and compact row statistics and reconstructs local probabilities when needed.

Check the invariant

A later tile introduces a score larger than every earlier score. What two stored objects must be rescaled?

Both the old shifted exponential sum \(\ell\) and the old unnormalized output numerator \(\widetilde o\). Multiplying each by \(e^{m_{\text{old}}-m_{\text{new}}}\) puts old contributions into the new maximum’s coordinate system.

One-minute derivation

\[ m'=\max(m,\max s_B),\quad \ell'=e^{m-m'}\ell+\sum_{j\in B}e^{s_j-m'}, \] \[ \widetilde o'=e^{m-m'}\widetilde o+\sum_{j\in B}e^{s_j-m'}v_j,\quad o=\widetilde o'/\ell'. \]

Five-question self-test

1. What is IO-awareness?
2. Why is the running maximum required?
3. What gets saved for backward?
4. Which complexity remains quadratic?
5. Why might a short-sequence model see little end-to-end gain?

1. Design around movement between HBM and on-chip memory. 2. Stable exponentials and mergeable blocks. 3. Outputs plus compact normalization state, not full probabilities. 4. Dense \(QK^\top\) and \(PV\) arithmetic. 5. Launch overhead or other layers can dominate.
